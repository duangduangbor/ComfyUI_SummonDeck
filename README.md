# 🎴 怪兽牌组 · SummonDeck

**Character cards for ComfyUI — keep the same character across every workflow.**

把角色 / 场景存成带缩略图的卡片，选几张**上台**，然后在提示词里打 `@卡名` 把它的参考图送进模型。
一张卡 = 一张底稿 + 一组多视图 + 一句身份描述，`@` 到哪张工作流都还是这张脸。

> 名字的来历：游戏王里怪兽卡要**召唤到场上**才起作用，这里的卡也要**上台**才被 `@` 认。
> 英文 SummonDeck = summon（召唤）+ deck（牌组）。

两层结构是核心设计：

```
第一层  角色库（全部卡片）
          ↓  点选 → 上台
第二层  工作台（本次要用的几张）
          ↓  @ 只认台上的卡
        提示词
```

这样卡片攒到几百张也不会在 `@` 的时候翻半天。

建卡时先定名字和一张**底稿**（自己框一张，或让 AI 画一张），之后所有补图都以它为参考；
角度不够就一键补齐，模型和提示词都已经替你配好了。

---

## 装

放进 ComfyUI 的 `custom_nodes` 目录，**目录名必须是 `ComfyUI_SummonDeck`**（前端按这个名字取 `style.css`，改名就白屏）。

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/duangduangbor/ComfyUI_SummonDeck.git
```

不使用 git 的话，从 [Releases](https://github.com/duangduangbor/ComfyUI_SummonDeck/releases) 下压缩包，解压后把 `ComfyUI_SummonDeck` 文件夹整个放进去。

重启 ComfyUI，画布空白处双击搜索 **🎴 怪兽牌组 · SummonDeck**（分类：`怪兽牌组`）。

无第三方依赖，只用 ComfyUI 自带的 torch / numpy / aiohttp。

> 旧的 `ComfyUI_CharacterWorkbench` 目录要先删掉，否则节点会注册两份。
> 节点类型名仍是 `CharacterWorkbench`（故意没改），所以以前存的工作流照常打开，不会变红。

## 用

### 1. 新建角色

节点上点 **「角色库 ▸」** → 右上角 **「＋ 新建卡」**，弹出一个小窗，只问两件事：**叫什么、长什么样**。

名字就是 `@` 的时候打的那个词，起短一点。分类默认有「角色 / 场景 / 道具」，
双击分类标签可以改名、改色、删除。

底稿（相当于这张卡的封面）有两条路：

#### 路一：上传一张自己框

点底稿区选图，会先进**裁切器**，微信头像那种交互：

- **框不动，图动。** 拖图片调位置，滚轮缩放，框外部分半透明压暗 —— 最后裁掉的正好是你没框进来的那块。
- 比例可以切 1:1、3:4、2:3、4:3、16:9、原图比例。默认 3:4（竖构图，适合全身）。
- 缩放有下限：图永远盖满框，不会在边缘露出空白。
- 输出长边限 1536 —— 参考图再大对模型没帮助，只会拖慢上传和预缩放。

这么设计是因为**素材常常是一整张拼图**（多视图设定表、带白边的商品图、一整页立绘）。
让系统自动判断"哪一块是脸"很难，让用户框一下很简单。

框错了不用重来：底稿区有「重新裁切」和「换一张」。

#### 路二：让 AI 画一张

没有现成图就点「没有现成图？让 AI 画一张」，写一句描述（谁、穿什么、什么气质），
选竖构图 / 方形 / 横构图，它会用 Qwen-Image 2.1 直接画一张当底稿。

画出来不满意可以重画。8GB 显存上一张大约 105 秒。

两条路的产物落在同一个地方：卡片的 `main`。之后所有补图都以它为参考。

#### 补齐剩余信息

建完卡再进抽屉补其他东西：

- **重新分类**：抽屉里的「分类」下拉直接换；想当场建个新分类，选最底下的 **「＋ 新建分类…」**，填名字和颜色，这张卡会直接归进去。
- **标记色**：抽屉里的「标记色」色板（或台上缩略图左上角的小圆点）。给不同的卡不同颜色，写提示词时一眼能看清哪个 `@` 是谁。
- 补充图：一张卡可以再挂多张（侧脸 / 全身 / 服装），默认不送出去，要在设置里打开。

### 2. 上台

在角色库里**点卡片** = 上台 / 下台。右上角打勾就是上台了。

底部那条显示当前台上有什么，点 `×` 可以撤下。

台上每张卡的左上角有个小圆点：**深灰 = 没标记色，彩色 = 已标记**，点它就能改。

### 3. 写提示词

节点上那个大框就是提示词框。

打 `@` 会弹出候选，**列表里只有台上的卡**。方向键选、回车确认，或者直接点。

`@` **不需要先打空格**：`然后@阿离`、`看着@雨夜街头` 都能直接弹。只有邮箱那种「字母数字紧贴 @」的情况不会弹，免得误触。

`@` 后面打几个字可以过滤，比如 `@阿` 只剩名字里带"阿"的。

也可以直接点工作台里的缩略图，它会把 `@卡名 ` 插到光标处。

**台上的卡设了标记色之后，提示词里的 `@名字` 会直接用那个颜色显示**（加粗），扫一眼就知道每个引用指谁。

### 4. 角色设定（让 `@` 背后不只是一张图）

抽屉里「标记色」下面那块。三栏，职责完全不同：

| 栏 | 写什么 | 送不送模型 |
|---|---|---|
| **身份锚定** | 只写**看得见**的：发色、发型、瞳色、体型、标志性配饰 | ✅ 默认送 |
| **可变项** | 明确允许模型改什么：`保持面部与发型不变，可换服装与场景` | ✅ 默认送 |
| **详细设定** | 人设、经历、口头禅、关系 —— 给人看的 | ❌ 默认不送 |

`@阿离` 在句子里还是只显示成 `image 1`，但**送进模型的提示词最前面会多一整块**：

```
image 1 是阿离。外观：黑长直、琥珀瞳、左眼下泪痣。保持面部与发型不变，可换服装与场景。
image 2 是雨夜街头。外观：湿润柏油路、霓虹招牌、地面积水反光。可换时间与天气。
以上每个编号对应各自的参考图，请分别按对应图像还原，不要互相混用特征。

然后image 1 转身走进image 2，回头看镜头
```

（最后那句「不要互相混用特征」只在**两张以上**卡带设定时出现。）

**为什么要分三栏，而不是给一个大描述框：**

Qwen-Image-Edit 这类模型的文本编码器是多模态的，确实会读你写的字。但它**对指令的响应远强于对外貌描写的响应**，尤其 cfg≈1.0 的时候文本约束本来就弱。写两百字自然语言外貌，很容易变成"氛围词"，把人物往*描述中的样子*拉，反而比不写更漂。所以：

- **身份指纹**（短标签）是补丁 —— 参考图角度不全、被遮挡、离得远时，它给模型一个语义锚；
- **可变项声明**是护栏 —— 不说清，模型要么不敢改，要么乱改；
- **长段人设**是资料，送进去只会稀释视觉信号。

**别指望它救参考图。** 角色漂移的成因按影响权重排是：参考图角度覆盖不足 > 参考图与目标分辨率差距 > 背景污染 > 多角色串扰 > 步数不足 > 提示词里有冲突的外貌词。文本设定排在最后。**同角色补两张侧脸 / 全身，比多写两百字管用得多。**

发送策略在 **「⚙ 设置」→ 角色设定** 里改（不发送 / 只发身份锚定+可变项 / 全发）。单张卡也能单独关掉（抽屉里那个勾）。

设定模板同样可改，占位符：`{ref}` `{name}` `{identity}` `{variable}` `{detail}` `{n}` `{i}`。某个占位符为空时会自动清掉留下的空壳（`外观：。` 这类）。

### 5. 快捷按钮

节点底部那一排。点一下把文字插到光标处，可以连着点着拼。

**这一排最后有个 ⚙**，点它直接跳到角色库的「⚡ 快捷按钮」页，增删改都在那；每个按钮 = 一个名字 + 一段提示词。

### 6. AI 补图（给一张图，出多视图）

入口：卡片编辑抽屉 → 「补充图」标签右侧的 **AI 补图**。

它治的是角色漂移的**第一主因：参考图角度覆盖不足**。一张只有正面的卡，
`@` 出去模型只能自己编侧面和背面 —— 补一张多视图设定表，比写两百字外貌描写管用。

#### 三种模式，别混着理解

| 模式 | 怎么出图 | 单张重跑 | 预设 |
|---|---|---|---|
| **参考编辑** `set` | 每个视图都拿卡片主图当参考，独立跑一次 | ✅ 点哪张重跑哪张 | Qwen-Image 2.1 参考图编辑 |
| **整表** `sheet` | 一次前向画出**一整张**多视图设定表 | ❌ 只能整张重出 | FLUX.2 QuadView、Krea2 七区表 |
| **文生图** `t2i` | 没有参考图，纯文字画一张 | 只用来做底稿 | Qwen-Image 2.1 生成底稿 |

`t2i` **不出现在补图面板里**。它的用途只有一个：新建角色时手里还没图，先画一张当底稿。

**整表为什么不能拆格重跑**：四个格子是模型一次前向联合生成的，构图、光照、比例互相咬合；
你把左下那格切出来重跑，新图和另外三格必然接不上。所以「单张重跑」只在参考编辑模式成立。

界面会按所选预设自动切换：整表模式只给一句说明，参考编辑模式列出**一排缩略图卡**，
一个角度一张卡 —— 卡上是这个角度**现在长什么样**（还没补就拿底稿压暗占位，右上角标「未补」），
卡下是角度名和该角度「该长什么样」的引导。

**鼠标移到任意一张卡上**，底部浮出两个入口：

- **AI 补这张**：只跑这一个角度，不影响别的格子。这个角度已经有 AI 图时按钮变「AI 重补」，
  换个种子重画并替换。
- **手动上传**：从本机选一张，先框选（比例已按这个角度预设好）再进这一格。

左上角那个小勾是给底部「开始补图」用的（决定批量跑哪几格），不是主操作 ——
只想补一张的时候不用先勾，直接悬停点「AI 补这张」就行。

#### 每个角度该长什么样，面板上就写着

选视图这一步最容易踩的坑不是勾错，是**不知道"侧面全身"到底要拍到什么程度**——
结果传一张只有半张脸的图，裁出来全是肩膀。所以每张卡下面直接印一句：

| 角度 | 引导 | 裁切比例 |
|---|---|---|
| 面部特写 | 头部到肩，正对镜头，眼睛看镜头，背景干净 | 1:1 |
| 正面全身 | 全身站直，双臂自然下垂，正面朝镜头，头顶到脚都在画面里 | 2:3 |
| 四分之三侧 | 身体侧转约 45°，脸仍朝镜头，全身 | 2:3 |
| 侧面全身 | 正侧身 90°，全身，能看清鼻尖到后脑的轮廓线 | 2:3 |
| 背面全身 | 背对镜头，全身，能看清后脑和后背的服装结构 | 2:3 |
| 动作姿态 | 一个典型动作姿势，全身，别裁到手脚 | 2:3 |
| 表情集 | 同一张脸的表情小拼图（平静 / 微笑 / 惊讶 / 严肃），或单张大头照 | 1:1 |

这段文案和真正喂给模型的 edit 指令写在同一个文件里（`presets.py` 的 `VIEW_GUIDES`），
不是各写一份 —— 两边说的要不是一回事，用户照着引导传了图，AI 却按另一套理解，那才是真的坑。

#### 手里已经有图？直接传，不用等 AI

每个角度右边有个 **上传**。点了先弹裁切框（**比例已经按这个角度预设好**，
不用自己调），框完直接进这一格：

- 走的是和新建角色同一套微信式裁切：框不动、图能动，拖动平移 + 滚轮缩放。
- **同一个角度只留一张**：再传一次就是替换，旧文件（含缩略图）一起删掉，不会越堆越多。
- 传完卡片右上角标 **「手动」**，和 AI 出的 **「AI」** 分开 —— 两者可靠性不一样，
  你该知道这张是怎么来的。
- 手动传的图在「已补过的图」里按钮是 **换图**（没有 seed 可重跑），AI 出的才是「重跑」。

抽屉里「补充图」旁边的 **＋** 现在也会先弹裁切框（默认原图比例），
那是加一张**没有角度归属**的普通补充图 —— 素材常是一整张设定表，不裁会把别人的脸也一起挂进去。

#### 参考编辑是真的把图喂进去，不是靠文字猜

Qwen-Image 2.1 的参考编辑把主图直接编进条件（`TextEncodeQwenImage21` 吃 `images.image_1`），
再按指令改写：「换成正面全身」「换成左侧面」「只拍脸和肩」。
所以脸型、发型、服装都跟着原图走 —— **不需要 IPAdapter / InstantID / reference-only ControlNet**。
旧版靠身份描述硬凑一致性的做法已经不需要了。

每个视图的指令和尺寸都在 `presets.py` 的 `VIEWS` 里写死，
换画幅用 `EmptyLatentImage` 覆盖，不改模型侧的 latent。

#### 它会自动认出你装了什么

不需要手动指定模型。补图预设**只声明需要什么架构**，真正的文件名在运行时探测：

| 架构族 | 怎么认出来的 | 能用的预设 |
|---|---|---|
| FLUX.2 | `double_blocks` + `double_stream_modulation_img` | FLUX.2 整表 |
| Krea 2 | `blocks.N.attn.wq` + `txtfusion` | Krea2 整表 |
| Qwen-Image | `transformer_blocks` + `txt_in` + `img_in` | 参考图编辑、生成底稿 |
| FLUX.1 | `double_blocks` + `guidance_in` / `vector_in` | —（未配预设） |

判断依据是**读 safetensors 头里的层命名**，不是猜文件名 —— 因为文件名经常乱起
（本机 `noctQUncensoredRealism...` 那个其实是 Qwen-Image 架构，不是 FLUX）。

缺模型的预设会灰掉并写明缺什么，比如「缺 unet（qwen）」。
**装好模型后点面板外重开就会重新探测**，不用重启 ComfyUI。

#### 前提：整表模式要专用 LoRA

- FLUX.2 整表要 `QuadView_klein9b_v1`（四视图）或 `TripleView_klein9b_v1`（纯三视图）
- Krea2 整表要 `DynamicCharacterSheet_krea2_v1`

没有这些 LoRA，模型不会凭空知道"要画几个视图、怎么排版"。缺了就在面板里灰掉。

#### 8GB 显存实测耗时

| 预设 | 尺寸 | 耗时 |
|---|---|---|
| Qwen 参考图编辑（20 步，单视图） | 832×1216 | 约 360 秒 |
| Qwen 生成底稿（20 步） | 832×1216 | 约 105 秒 |
| FLUX.2 整表（8 步） | 1536×1024 | 约 100 秒 |
| Krea2 整表（10 步） | 1536×1024 | 约 190 秒 |

跑的时候按钮变成**取消**，点了会真的把任务从 ComfyUI 队列里撤掉并中断采样，
不是只改个状态。同一时间只跑一个，不会叠着占显存。

#### 出图自动进卡

跑完直接挂进这张卡的补充图，不用手动拖文件。入库记了 `presetId / seed / view`，
所以**隔天重启之后还能点「重跑这张」** —— 重跑会替换原来那张（旧文件同时删掉），
不会越补越多。

#### 它记得你补过什么

面板里有一块 **「已补过的图」**，列出这张卡以前补出来的每一张（带缩略图、角度名、
来源和 seed），可以直接「重跑 / 换图」或「删除」。
更直观的是上面那排视图卡：**补过的角度直接显示那张图**，没补的只有压暗的底稿和「未补」标 ——
一眼能看出哪几个角度还缺，不会把同一个角度补三遍。

#### 关掉面板不会停任务

以前点一下面板外面就关了，跑一张要六分钟，手滑一次界面就没了。现在：

- **只有 ✕ 能关**（Esc 也行，但跑着的时候会先拦一句）。
- **关掉只是关界面，任务在服务端继续跑。**
- **重新打开会自己接回来** —— 按钮直接是「取消」，状态接着显示「进行中 · 面部特写 采样中（1/5）」。
  不会再给你一张空白面板，让人以为没在跑、又点一次。

#### 一个必须知道的限制

**底稿决定上限。** 参考编辑和整表都拿卡片主图当参考，主图糊、角度怪、背景杂乱，
补出来的每一张都会继承这些毛病 —— 所以新建角色那一步的裁切框要认真框。

补出来的图都进 extras，不覆盖主图。所以要换底稿，得在新建那一步就框对。

#### 不满意就自己改工作流

补图面板右上角有个 **编辑工作流**。点进去会把当前预设载入 ComfyUI 画布，
换 LoRA、调步数、改采样器、加 ControlNet 都随意，改完点「保存」立刻生效。

三个必须知道的行为：

- **你原来的画布会被临时替换，返回时自动还原。** 载入前先存一份快照，
  点「保存并返回」或者在编辑器里返回，都会把原画布原样放回去。
- **「恢复内置」只删你的改动，不碰卡片数据。** 顶部状态条和设置页各有一个入口。
- **保存前会先校验。** 节点定义缺了、必填输入空了、连线断了，都会拦住并告警，
  不会存成一份跑不起来的画布。

改过的预设会在补图面板上标出来，方便你记得哪份不是原装的。

#### 看大图，和「保存」

缩略图只有 4:5 一小块，判断一张侧脸能不能用是不够的。

**点任意一张图就放大看**（视图卡、「已补过的图」、本次结果都行）：

- 图占满屏幕，`←` `→` 在同一组图里前后翻，标题底下写着这张的角度和 seed
- 点图片本身（或空格）在「适应窗口 / 1:1 实际像素」之间切，看噪点和发丝用得上
- `Esc`、点背景、右上角 `✕` 都能退出来 —— 关的只是大图，补图面板还在

**底部多了一个「保存」。** 它存的是**身份描述**：补出来的图出完就自动进卡了，
只有这段文字以前是跟着任务走、不落盘的，手打完直接关面板等于白写。现在：

- 改过描述，保存按钮会亮起橙边和一个小圆点，提醒你有未保存的改动
- 点它，或者按 `Ctrl+S`，写回卡片
- **懒得点也行 —— 按 `✕` / `Esc` 关面板时会先自动保存**，存不上就不关，不会悄悄丢掉

## 引用编号怎么算

**规则只有一条：`@` 在提示词里出现的先后顺序，就是参考图的编号顺序。**

| 你写的 | 模型收到的 | 送出的图 |
|---|---|---|
| `@阿离 站在 @雨夜街头 的路灯下` | `image 1 站在 image 2 的路灯下` | 1=阿离 2=雨夜街头 |
| `@雨夜街头 的路灯下站着 @阿离` | `image 1 的路灯下站着 image 2` | 1=雨夜街头 2=阿离 |
| `@阿离 看着 @雨夜街头，又看看 @阿离` | `image 1 看着 image 2，又看看 image 1` | 只送 2 张（阿离只算一次） |
| 一个 `@` 都没有 | 前面自动补 `image 1 image 2.` | 台上所有卡，按上台顺序 |

名字有包含关系也安全：台上有「阿离」和「阿离的姐姐」时，`@阿离的姐姐` 会正确匹配长的那个。

台上没有的名字会原样保留，并在「引用对照」输出里告诉你哪个没匹配上。

## 引用标记要按模型改

`image 1` 不是所有模型都认。在角色库 **「⚙ 设置」** 里改模板：

| 模型 | 模板填 |
|---|---|
| Qwen Image 2.1 / Flux 2 Klein / 大多数 | `image {n}` |
| MiniMax H3 | `<Picture {n}>` |
| 自己定 | 随便写，`{n}` 从 1 算，`{i}` 从 0 算 |

## 输出怎么接

节点有 5 个输出：

| 输出 | 类型 | 是什么 |
|---|---|---|
| **参考图** | IMAGE | 按 `@` 顺序排好的图，一个 batch |
| **提示词** | STRING | 已经替换好标记的文本 → 接文本编码器 |
| **引用对照** | STRING | `1 ← 阿离 / 2 ← 雨夜街头` + 带设定送出了几张，核对用 |
| **张数** | INT | 这次送了几张 |
| **原始提示词** | STRING | 你写的原文，不替换 `@`、不自动加 `image 1` 编号 |

- 多张参考图是 **一个 IMAGE batch**。单图模型直接接第一帧，多图模型按顺序消化。
- 要拆开用，接 `ImageFromBatch` 按 index 取。
- 尺寸不一致的图会**等比缩放后居中补灰**到同一画布（batch 要求同尺寸）。
- 参考图默认限到 **1 百万像素**，8G 显存够用。设置里能改。

> **什么时候用「原始提示词」？**
> 给那些提示词里要写固定触发句的工作流用 —— 比如 Character Sheet（四视图/三视图）、
> 以及 Qwen2.1 这类「保持参考图1…」的参考生图工作流。
> 「提示词」那一路在台上没有 `@` 时会自动补 `image 1 image 2 ...` 前缀，
> 对固定触发句是污染，所以单独留了一路干净的原文。
>
> **注意：两路都会在开头带上角色设定块**（设置里可以关）。「原始」指的是不替换 `@`、
> 不自动补编号，**不是**"不带任何附加信息"。
>
> 所以：
> - 想让 `@阿离` 变成 `image 1` → 接第 2 路 **「提示词」**
> - 想原样保留自己写的固定句式 → 接第 5 路 **「原始提示词」**，此时 `@` 只负责选图，
>   文本里的 `@阿离` 不会被替换（设定块会替你说明 `image 1` 是谁）

> **工作流只吃第一张图怎么办？**
> 像 `工作台.参考图 → ImageFromBatch(0)` 这种只取 index 0 的接法，台上放 **一张卡** 时设定块和它是
> 1:1 对应的；放多张时，设定块会多列出模型根本没收到的那几张，属于自找干扰。要么只放一张，
> 要么把 batch 拆开分别接 `image_1` / `image_2`。
>
> 现成例子见你之前那份「Qwen2.1 参考出图」使用说明。

## 数据存在哪

```
ComfyUI/user/default/character_workbench/
    library.json          卡片信息 / 分类 / 工作台 / 快捷按钮 / 设置
    assets/<卡片id>/      main.png 原图 · thumb.jpg 缩略图
                          e_*.png 补充图（含 AI 补图产出）· th_*.jpg 对应缩略图
    presets/<预设id>.json 你在画布上改过的补图工作流（没改过就没有这个文件）
```

补图预设是**两层**的：内置基线在插件目录 `presets_ui/<预设id>.json`，
你改过的版本存到上面那个 `user/` 路径下，覆盖基线但不破坏基线 ——
所以「恢复内置」永远能退回去，插件升级也不会把你的改动冲掉。

`user/` 目录不会被 ComfyUI 更新覆盖，卡片是长期安全的。

工作台是**全局**的（存在 library.json 里），不是每个节点各一份。所以：

- 开几个工作台节点，看到的是同一批台上的卡
- 提示词是各节点自己的，互不干扰
- 关掉 ComfyUI 再打开，台上的卡还在

## 已知边界

- 节点内容区上方有约 80px 空白 —— 这是 ComfyUI 把 DOM 组件放在节点下方固定偏移导致，不是留白写错。
- 节点内各部分高度的规矩：顶部按钮行固定、卡片条固定 92px、**多出来的空间全给提示词框**，所以节点拉高就是提示词框变高，底部不会留空。内容区高度是常量，不随节点尺寸回算，因此节点不会自己越变越长（踩过两次坑，见 `js/cw-workbench.js` 里 `MIN_CONTENT_HEIGHT` 的注释）。
- `@` 匹配是**最长优先**的纯文本替换。台上有「阿离」时写 `@阿离站着` 会正常匹配「阿离」，但如果台上恰好有张卡叫「阿离站」，它会匹配那个长的。遇到怪情况就给名字后面加个空格。
- 主图建议用竖构图（3:4），和补图预设的输出比例一致；缩略图会按 1:1 居中裁切。
- **角色设定不是万灵药**。它补的是"参考图看不清的地方"，补不了"参考图不够"。同角色有 3 个以上角度时，设定块带来的收益会明显下降；只有一张正面图时，它的收益最大但也最有限。
- 卡片上那个小圆点 = 带角色设定（彩色 = 会送，灰色 = 关掉了）。节点工作台上的小绿点同理。
- 提示词框是「透明文字的 textarea + 下面一层彩色文字」叠出来的。输入法、选区、滚动都还是原生行为，但**字色由下层决定**：如果哪天你在系统里换了很怪的字体导致两层错位，告我，把下层宽度按字宽重新算一遍就行。

### 补图相关的边界

- **补图任务记录只在内存里**。重启 ComfyUI 后，"正在跑的那个任务"查不到了，但已入库的图还在，而且**「重跑这张」照样能用** —— 它靠的是入库时记在 extras 里的 `presetId / seed / view`，不依赖任务记录。
- **同一时间只跑一个补图任务**。8G 显存并行会炸，排队是刻意的。
- **整表模式改不了画幅**。1536×1024 是这些 LoRA 训练时的版面，实测 1792×1024 会多出一格、2048×1024 直接崩布局，所以固定死了。
- **SDXL / SD 1.5 已从预设里移除**。它们逐张出图要靠 IPAdapter / InstantID 这类图像条件才能锚住同一张脸，链路复杂且效果不稳；现在统一换成能直接吃参考图的 Qwen-Image 2.1，一个模型管底稿和参考编辑两件事。
- **参考编辑一张要 6 分钟左右**（8GB 显存，832×1216，20 步）。这不是 bug，是显存换算力。嫌慢就减步数，或者只补真正缺的角度。
- **底稿裁切的输出不保留 EXIF**。裁切走的是 canvas 重绘，方向已经摆正了，但拍摄参数那类元数据会丢 —— 对出图没影响。
- 整表出的是**一张合图**，不是四张独立文件。Qwen 这类编辑模型看整张合图也能取到多角度信息，所以没做自动切图 —— 切了反而会误导"这张能单独重跑"。
